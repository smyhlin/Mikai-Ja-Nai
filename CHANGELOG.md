# Changelog

## 0.1.0 — Unreleased
### Linux desktop portability (2026-10-27)

- Hardened Compare capture cancellation, destruction, PNG fallback and OpenGL surface restoration; PiP handles window-manager close through its owner. Wayland compositor policy governs move/resize and always-on-top.
- Added opt-in XDG autostart and Open With desktop registration, with default-app selection left to the user rather than forced MIME associations.
- Linux Standard AnimeJaNai supports NVIDIA TensorRT with a compatible fork and CUDA/TensorRT; DirectML and the private Native backend remain Windows-only. The current official AnimeJaNai v0.17.1 runtime is API/ABI 9; its Linux and Windows runtime archives are separately pinned/importable. The current Windows DEV archive's headers declare ABI 9. The Linux runtime archive is separately pinned; the `mpv-fork` source entry still identifies ABI-8 commit `63d127174d8f70336c82a22408929e2bc301edcb`, while the Windows archive has separate source commit `b4f9f5bfed18d5ce610af28024986410dd9bdaae`. The Linux archive's build/source correspondence is not established; archive identity does not prove GPU inference. The old official v0.9.0 ABI-8 pair and separately patched private MSVC AJI ABI-8 build are historical and not interchangeable with v0.17.1. The 80 MB Linux encoder archive is a separate optional offline tool, not a playback dependency; it is not automatically downloaded or adopted, and its FFmpeg and redistribution rights remain unresolved.
- Manager controls include temporal frames (Auto, 1, or odd 3–15), temporal scene threshold, upscale enable/disable and temporal fix. Official v0.17.1 sources map RIFE code 4262 to regular `rife_v4.26`, not heavy RIFE; source mapping does not establish inference. TensorRT 11/CUDA 13 closure follows the current backend dependencies.
- Benchmark reports use Linux app-local data; benchmark clips are externally supplied, not redistributed. Invalid model choices are disabled and paths are case-sensitive. AI data still requires writable executable-adjacent `native/`.
- Updated the pinned Windows mpv DEV archive and Linux private runtime bundle to the 2026-10-24 releases. The Windows DEV archive provides headers, import library and `libmpv-2.dll`; its similarly dated CLI archive contains no libmpv DLL and is not used or bundled. The Linux bundle carries `libmpv.so.2` (with full-version file `libmpv.so.2.6.0`). The updated Windows DEV archive contains ABI-9 host entrypoint name markers (`aji_ingest`, `aji_infer_seq`, `aji_temporal_radius`, `aji_temporal_reset`, `aji_rife_before_upscale`, `aji_pre_resize`, `aji_resize`, `aji_infer_rife`); these strings are marker evidence only, not proof that entrypoints are exported or callable, executed behavior, or GPU inference. Matching ABI-9 markers have not been recorded for the Linux runtime binary. No Windows/Linux runtime-pass, behavior, or GPU validation was run for this pin update.
- Linux build, focused-test and real-video desktop acceptance instructions are in [building](docs/building.md#linux-desktop-acceptance); these changes are not a claim of completed Linux hardware or visual validation.

### HDR and playback timing (2026-10-26)

- Added Auto (default), Stable and Vivid HDR playback policies in Settings → General. They configure tone-mapping, peak-detection, percentile, gamut-mapping and dither-depth options; Stable disables adaptive peak computation. Unsupported options are refused tolerantly by older system runtimes. A pre-correction GPU run warned that Stable's `gamut-mapping-mode=perceptual` is unsupported by `vo_gpu` and falls back; current source uses Stable `clip`, which passed the current fork/stock HDR probes.
- Anime4K is gated to sources with known SDR transfer metadata. Native AJE/AJI remains available for known SDR; HDR requires both positive HDR identification and the explicit override. Unknown metadata cannot satisfy that override. The application reports the actual Qt FBO attachment format; that observation is not a 10-bit display or HDR-passthrough claim.
- Added module-bound, version-aware mpv pacing-clock handling and client frame pacing, with `MIKAI_CLIENT_FRAME_PACING=0` as the pacing rollback. Buffered frame timing diagnostics are available through `--frame-timing-log`; `MIKAI_HDR_FIXES=0` disables HDR policy changes and the two HDR processing gates, but does not falsify FBO probing.
- Corrected pause/source/context repaint cancellation and immediate redraw/repeat handling. Related P2 work includes background coalesced history persistence, dirty quality-cache persistence, bounded/cancelable HTTP transport and archive acquisition, redirect/authentication guards, and safer icon caching.
- Addressed the Unix decimal-comma `LC_NUMERIC` conflict with `mpv_create`: startup sets the C numeric locale after Qt initialization, and direct libmpv core creation enforces it too. Qt's UI locale remains unchanged. This is a locale-specific startup fix, not a general Linux rendering fix.

### Release preparation

- Added an original Mikai icon for the application, Windows packages and Linux desktop integration.
- Added Windows x64 portable ZIP and per-user installer generation, payload inventories, checksums and provenance records.
- Added Linux x86_64 packaging with explicit system-mpv and private bundled-mpv profiles, optional Qt deployment and relative runtime search paths.
- Added source-snapshot packaging that hashes the bytes actually archived, excludes private/runtime data and records when a worktree is not equivalent to a commit.
- Added CI and protected release preparation with trusted-tag ancestry, artifact-integrity and explicit redistribution gates.

### Corrections

- Preserved processing-off startup even when enhancement presets were previously saved; processing requires an explicit request.
- Preserved pause intent and stopped-source state across OpenGL context recreation.
- Resolved explicitly selected runtime bundles through the validated resolver instead of constructing untrusted loader handoffs.
- Separated the localized runtime-availability summary from the retained technical refusal cause.
- Made installer Start Menu group selection effective and verified Unicode shortcut targets through the native Windows interface.
- Added installer payload-hash, upgrade/uninstall data-preservation and integration-preservation checks.
- Fixed Windows bundle-inspector symbol lookup recursion and Linux shared-library classification; added actual Standard-bundle verification and unsupported-Native refusal contracts.
- Corrected isolated Windows process ownership so console hosts are not mistaken for test descendants; exact child exit codes and bounded descendant cleanup are verified.
- Added real registry-sandbox coverage for foreign registration preservation and partial-failure rollback without opening Windows Settings.
- Added fullscreen aging diagnostics with explicit foreground, playback-owner, source-epoch and OpenGL-context validity checks; invalid desktop observations remain failures rather than being reported as visible playback proof.
- Removed accidental patch markers from source/notice files and excluded root probe scratch files from public source selection.

### Test and CI infrastructure

- Added bounded `--start` scene selection and explicit `--natural-media` controls to the HDR and aging probes. Natural footage does not claim authored-barcode frame-order proof or require a visible tone-map difference in every dark frame; default synthetic-fixture assertions remain strict.
- Added same-paused-source Auto captures, optional fullscreen aging, diagnostic-only center-pixel observations, and a minimum valid-content-sample verdict. Fixed natural-media frame captures being discarded because they used a barcode-only source epoch.
- Replaced competing app/probe/test post-link shader-directory copies with one configuration-specific shader-staging dependency after an observed concurrent Linux copy failure.
- Moved the aging probe's full-resolution content hashing and vertical image flip off the GUI thread to one asynchronous worker job while keeping OpenGL readback on the GUI thread; sample metadata is immutable and GUI polling nonblocking. This changes probe instrumentation only and does not remove readback cost or establish an application rendering fix.

- Added `frame_order_soak_probe`, a long-soak harness for the periodic frame-order/pacing regression: one `--minutes` playback window asserting frame-counter continuity (no >2 s stalls while playing), per-source-segment drop-counter budgets and advancing frame-content hashes, with its own optional timing log. Registered as an `EXCLUDE_FROM_ALL` probe and exercised by the new nightly canary workflow.
- Split the hermetic `mikai_tests` ctest entry into one entry per registered suite (same launcher, same properties, one suite name each) while keeping the run-everything entry, so a hard crash in an early suite can no longer silently skip every later suite; CI's ctest invocation now runs the per-suite entries and excludes the one-shot blob.
- Added `mikai_provenance_check`, a dependency-free ctest that fails when the mpv archive pin in `cmake/FindOrFetchMpv.cmake` and the record in `packaging/provenance/windows-runtime.json` disagree on archive, URL, SHA-256, source commit or release tag.
- Added Linux sanitizer configure/build presets (ThreadSanitizer, AddressSanitizer+UBSan, UBSan with abort-on-first), `/W4` (without `/WX`) for the MSVC native shim, and manual-dispatch `sanitizers` and `bundled-runtime-smoke` CI lanes; the bundled lane replays the renderer smoke through the private libmpv closure exactly as the Linux archive packages it.
- Added a Linux/bash port of the fixture media generator, including the two HDR regression clips (10-bit PQ slow dark gradient; 10-bit PQ near-black temporal noise), and corrected the fixtures README's stale range/matrix pass-through claim.
- Added a documentation-claims review rule to the contribution checklist: a countable invariant in prose must name the command that verifies it.

### Distribution status

These are unreleased source changes and local preparation tools, not publication approval. Windows installers are unsigned. Linux archives still require compatible host graphics, audio and libc facilities. The supplied third-party mpv/FFmpeg builds have unresolved corresponding-source and license-fulfillment requirements; their public redistribution remains blocked. See [release status](docs/release-status.md) and [redistribution](docs/redistribution.md) for evidence and limitations.
