# Changelog

## 0.1.0 — Unreleased

- Keyboard seeks and the +85 control now resolve relative steps against mpv's current playhead rather than delayed UI progress, including PiP's own core. Absolute timeline and resume seeks are unchanged, and Compare invalidates pending captures for either kind. Timeline/speed and volume sliders honor the final release position and ignore unrelated button releases during a left-button drag. A lost left-button release ends the drag without committing the next hover position.

- Player rendering now retries temporarily suppressed paints without waiting for another mpv callback, isolates raw OpenGL rendering and processing-transition captures from Qt painter state, and invalidates framebuffer depth/format caches when their target changes. Windowed canvas sizing uses display aspect and rotation without changing the coded dimensions supplied to processing or source-resolution labels. These source fixes do not establish that all intermittent black frames are resolved.

- Settings Appearance now initializes accent, radius, gradient and general controls from the current saved appearance when the tab is built and when the dialog is reopened, including saved custom colors, with checked swatch indicators kept in sync. Preview, save, cancel, reset and live language/appearance refresh behavior are preserved.

- Title-page buttons now use the global corner radius, and secondary actions remain visibly outlined before hover. Watch, Episodes and More details share a wrapping hero action row; clicking either displayed title name copies it, with Enter/Space activation also available.

- Refined the title page's poster-led hero and episode workspace, with a prominent Watch/Continue action and clearer release and provider selection.

- Compare's Flicker export now offers GIF, animated WebP and silent Motion-JPEG MP4, with a folder chooser and completion actions. GIF uses adaptive per-frame palettes and dithering instead of the fixed 3-3-2 palette; MP4 playback support depends on the viewer.
- The Components page no longer labels the TensorRT runtime or GPU kernels installed when no Native runtime bundle is discoverable, or GPU kernels installed when no compatible resource pack is selected; empty directory-resolution results and unsupported GPU generations are not treated as installed. The same bundle/store availability decision feeds recommendations and acquisition checks on Windows and Linux.


- Cover-gradient and corner-radius previews now refresh already-loaded related-title artwork on title pages, instead of leaving its cached rounded image in the old appearance.

- The player's centered play/pause indicator becomes a loading indicator while the Compare window opens. Compare is constructed only after that frame is composed, so a repeated request or a close during startup cannot reopen it.
- Windows Setup now detects the registered version: the same version is offered as **Repair**, an older one as **Upgrade**, and a newer one is refused instead of replacing it. Settings, logs and acquired models still survive both paths.
- TensorRT engine-build progress stays above competing windows on Windows and X11 without taking keyboard focus. The overlay stops reasserting its position when hidden; Wayland stacking remains under compositor control.

- Successful bundle CLI contract checks remove their temporary copied runtimes instead of accumulating them in the build directory.

### AnimeJaNai fork identification, loader and engine build (2026-10-30)

- Windows could report `animejanai.core.unsupported` before filter attachment even when the pinned fork was present: admission required the old exact Windows DLL digest and client API 2.5, rejecting the updated DLL whose `animejanai` filter marker is present and whose client API is 2.6. Admission now requires a loaded Standard core, the resolved module to be in the validated runtime inventory, the filter name and its `trtexec-libdir` and `rife-model-dir` option markers, and client API 2.5 or newer. Markers are checked during worker-side runtime resolution and cached for playback; a stock module without them remains rejected.
- An isolated Windows run on an RTX 5090 with the TensorRT 11.3 runtime built the HD Performance model from a fresh graph: `trtexec` reported `PASSED`, the engine loaded, and the selected filter produced 320×180 → 640×360 output on a generated BT.709 H.264 clip. This is not a throughput, production-media or public-release claim. Installed runtime/model files were read and copied into a temporary store, not modified.
- AnimeJaNai no longer reports `animejanai.core.unsupported` on a Linux artifact that ships the fork. The check compared the module against an older Windows DLL's size and digest, which patchelf-mediated installs can never match; Unix modules are identified by the `animejanai` filter marker plus client API 2.5 or newer. The recorded Linux fork and current Windows fork report API 2.6; an older Windows fork reported 2.5.
- `animejanai.backend.failed: Failed to create inference context` is fixed. The fork resolves `libnvinfer.so.11` and its siblings by bare soname when it creates its inference context, and the store is not on the process loader path; `prepareAnimeJanaiPlan` records the closure folder in `AnimeJanaiPlan::backendLibDirs` and the surface preloads it `RTLD_GLOBAL` before attaching the filter.
- `animejanai.build.failed … (see .build.log)` with `sh: line 1: Wrapper/…: No such file or directory` is fixed. The fork hands `/bin/sh` the line `LD_LIBRARY_PATH=<trtexec-libdir> "<trtexec>" …` with that prefix unquoted, so the store path `…/Mikai Wrapper/…` split it and `trtexec` never started (exit 127). Both plan builders now pass `detail::shellSafeLibDir(...)`: a symlink mirror of the closure under a space-free temp root whenever the real path is splittable. With it, `trtexec` reports `&&&& PASSED TensorRT.trtexec`, writes the `.engine`, and playback upscales 1920x1080 to 3840x2160 on an RTX 5090 (TensorRT 11.3, sm_120).
- A packaged run now always leaves a log. An AppImage mounts its payload read-only, so `mikai.log` falls back to `AppLocalDataLocation` instead of being dropped, and AnimeJaNai failures are written under `[animejanai]` with their reason key.
- Contracts and the pre-release gate are documented in [`AGENTS.md`](AGENTS.md), [`native/README.md`](native/README.md) and [`docs/releasing.md`](docs/releasing.md); `TestAnimeJanaiRuntime` pins both the plan's loader folder and the shell-safe mirror, and `TestDiagnostics` pins the log fallback.

### Bundled libmpv runtime (2026-10-29)

- Every Linux artifact now ships our own libmpv instead of borrowing the host's. The runtime we pin was built without an FFmpeg TLS backend, so https provider streams failed with "No protocol handler found" — which is why the AppImage used to fall back to the host's libmpv. `packaging/mpv/build-tls-archive.sh` rebuilds FFmpeg at the same tag with the same flags plus `--enable-openssl`, replaces that family inside the archive and adds OpenSSL 3.0 from the Ubuntu 22.04 baseline; the mpv fork, libplacebo, shaderc, libass and Vulkan loader stay the published bytes. The rebuilt runtime decodes an https HLS stream through `MpvHandle` (duration 634.58 s, h264); the published archive returns nothing on the same URL.
- The bundled OpenSSL was compiled against the build distribution's CA paths, so `MpvHandle` now names the host's CA bundle unless the caller set `tls-ca-file` (`MIKAI_TLS_CA_FILE` overrides). Without it, TLS still failed on Arch and Fedora with a working backend.
- The runtime installs to a prefix-relative directory instead of always `<bindir>/mpv`: a directory named `mpv` in `/usr/bin` collides with the distribution's `mpv` package, so the Arch build uses `/usr/lib/mikai/mpv`. The Vulkan loader is kept in the bundle — the runtime links it, and a host without `vulkan-icd-loader` could not load the module otherwise.
- The Arch package adds the runtime archive as a source, depends on `qt6-base`/`libglvnd` instead of `mpv`, and installs the runtime under `/usr/lib/mikai/mpv`. The Debian package mounts the archive into its builder and no longer depends on `libmpv2`. The tarball and AppImage build with `-DMIKAI_LINUX_BUNDLE_MPV=ON`. Windows already shipped the pinned `libmpv-2.dll`; the `mpv-x86_64-*` runtime archive contains only `mpv.exe` and cannot supply it.

### Distribution packages (2026-10-29)

- Arch and Debian packages are now part of the release output. `packaging/linux/arch-package.sh` exports `HEAD`, builds with `makepkg` against Arch's Qt 6.12 with the bundled runtime archive as a source, and runs the repository's CTest gate before a package exists; the result installs to `/usr`, with the runtime under `/usr/lib/mikai/mpv`. `packaging/linux/deb-package.sh` builds inside Debian 13 through Docker, because the package's glibc floor is the build base's and no Debian-family release ships Qt 6.12: it installs Qt 6.12, the bundled runtime and the ICU 73 that SDK links under `/usr`, and no longer depends on a distribution mpv. Both scripts install what they built — the Debian one as an unprivileged user — and refuse a dirty worktree or a populated output directory. Recorded artifacts: `mikai-0.1.0-1-x86_64.pkg.tar.zst` (installed and removed in an `archlinux` container) and `mikai_0.1.0_amd64.deb` (installed in a clean `debian:trixie-slim`, `--version` and an offscreen start, then removed).

### Player chrome, watch state and update hygiene (2026-10-29)

- Playback now always starts at 00:00 and offers the stored position instead of jumping: once libmpv reports a length, the player asks "Continue from 12:34?" with **Continue** and **Start over**. Continue seeks, Start over clears the stored offset, and dismissing the box keeps it for the next open. Offsets shorter than 30 s are not stored; reaching 90 % of the length marks the episode watched and drops the offset. The title page shows the same state as a hairline progress bar, a `12:34 / 24:00` meta line and a **Continue** action in place of **Watch**. Verified by driving the real dialog: 45 s stored → Continue lands at 45.00 s, Start over stays at 0.12 s and raises `episodeResumeDeclined`, and no offset raises no prompt.
- The player footer names what is playing: **HDR** (HDR10/HLG), **DV** (Dolby Vision), **ATMOS** (E-AC-3/TrueHD) and a codec badge (H.264, HEVC, AV1, VP9, VP8). These read `video-codec`, `audio-codec` and the existing `video-params` observations; absence of a badge means the metadata was not reported, not that the source is plain.
- Corner radius and accent reach the player through one push model, as the accent already did: the application pushes `theme::radiusSmall()` at startup and on a customization change or save. Window controls, the title bar, dock, footer chip and the episode steppers all read it, so one step shapes every chrome surface. The steppers are a dedicated `EpisodeNavButton` rather than an `IconButton` over a shell-painted disc; the disc is gone.
- Custom-painted chrome and widgets enable antialiasing, `SmoothPixmapTransform` and device-pixel-ratio scaling, so icons and controls stay crisp at non-integer display scaling.
- Anime4K colour corruption on Wayland is fixed at the context, not per preset: the application requests a desktop OpenGL 3.3 core context before `QApplication`, because Qt otherwise produced GLES 3.2 and mpv ran its render API on it. Measured on a test frame, `hq_a` mean RGB was 48.9/107.3/121.5 on GLES against 120.0/124.2/126.0 on desktop GL (chain off: 120.8/124.9/126.9). The `hq_aa` chain order is corrected as well: auto-downscale-pre sits between the two upscale stages.
- The session is kept awake while something plays: logind's `idle` block, or the screen-saver interface when logind is unavailable, held per playing surface and released when the last one pauses or closes. `systemd-inhibit --list` shows the block for both the source build and the AppImage while playing, and none after close.
- The native store is usable from an AppImage and from a packaged install: `MIKAI_NATIVE_ROOT`, then an executable-adjacent `native/` when that directory accepts a write, then `AppLocalDataLocation/native`. Ownership checks anchor at the resolved store's parent rather than the executable's directory.
- Starting the application now clears what a killed install or download leaves behind — abandoned `scratch/` entries and `*.previous` backups after a day, and `aji-stage-*` trees and `*.partial` copies after an hour — and never an installed component, a model or a setting. This replaces deleting the native folder by hand after an update; a seeded store kept its just-created stage, its installed `trtexec` and an imported ONNX graph while the 3-day-old junk went, and two regression cases in `TestNativeBundle` pin both directions.
- Every build names itself: `--version` prints `mikai 0.1.0 (<rev>, built <UTC stamp>)` without needing a display, and the same line is logged at startup and carried by `applicationVersion`. A cross build states the revision through `-DMIKAI_BUILD_REVISION` because the checkout may not be readable inside its container. Distinguishing "the update did not apply" from "an older process is still running" no longer depends on deleting state.
- The title page no longer credits the cover: the credit line and its team chip are removed with their four catalogue entries. The release chip's context menu still opens a team, which is a different affordance.
- The Linux TensorRT pack now names the files the pinned 3.7.0 archives actually contain (`libnvinfer.so.11`, `libnvinfer_plugin.so.11`, `libnvonnxparser.so.11`, `libcudart.so.13`, `trtexec`), and `trtexec` is no longer a member of the `trt-runtime` pack: it is copied once by the AnimeJaNai provisioning step, where a second copy used to fail against `QIODevice::NewOnly` and abort the install with "trtexec could not be created". The 7-Zip listing validator no longer reads the always-printed, usually-empty `Symbolic Link =` field as a symlink.
- Local verification for these changes: harmonised CTest **55/55** on Linux, plus the recorded AppImage, portable-tree and wine-run Windows `--version` output (`0.1.0 (9372c03, built 2026-10-28T21:56:19Z)` for Linux). This is not a claim of a public release, of GPU inference, or of a green release gate.

### Test and CI infrastructure

- Added bounded `--start` scene selection and explicit `--natural-media` controls to the HDR and aging probes. Natural footage does not claim authored-barcode frame-order proof or require a visible tone-map difference in every dark frame; default synthetic-fixture assertions remain strict.
- Added same-paused-source Auto captures, optional fullscreen aging, diagnostic-only center-pixel observations, and a minimum valid-content-sample verdict. Fixed natural-media frame captures being discarded because they used a barcode-only source epoch.
- Replaced competing app/probe/test post-link shader-directory copies with one configuration-specific shader-staging dependency after an observed concurrent Linux copy failure.
- Moved the aging probe's full-resolution content hashing and vertical image flip off the GUI thread to one asynchronous worker job while keeping OpenGL readback on the GUI thread; sample metadata is immutable and GUI polling nonblocking. This changes probe instrumentation only and does not remove readback cost or establish an application rendering fix.

- Added `frame_order_soak_probe`, a long-soak harness for the periodic frame-order/pacing regression: one `--minutes` playback window asserting frame-counter continuity (no >2 s stalls while playing), per-source-segment drop-counter budgets and advancing frame-content hashes, with its own optional timing log. Registered as an `EXCLUDE_FROM_ALL` probe and exercised by the new nightly canary workflow.
- Split the hermetic `mikai_tests` ctest entry into one entry per registered suite (same launcher, same properties, one suite name each) while keeping the run-everything entry, so a hard crash in an early suite can no longer silently skip every later suite; CI's ctest invocation now runs the per-suite entries and excludes the one-shot blob.
- Added `mikai_provenance_check`, a dependency-free ctest that fails when the mpv archive pin in `cmake/FindOrFetchMpv.cmake` and the record in `packaging/provenance/windows-runtime.json` disagree on archive, URL, SHA-256, source commit or release tag.
- Added Linux sanitizer configure/build presets (ThreadSanitizer, AddressSanitizer+UBSan, UBSan with abort-on-first), `/W4` (without `/WX`) for the MSVC native shim, and manual-dispatch `sanitizers` and `bundled-runtime-smoke` CI lanes; the bundled lane replays the renderer smoke through the private libmpv closure exactly as the Linux archive packages it.
- Added a Linux/bash port of the fixture media generator, including the two HDR regression clips (10-bit PQ slow dark gradient; 10-bit PQ near-black temporal noise), and corrected the fixtures README's stale range/matrix pass-through claim.
- Added a documentation-claims review rule to the contribution checklist: a countable invariant in prose must name the command that verifies it.

### Distribution status

These are unreleased source changes and local preparation tools, not publication approval. Windows installers are unsigned. Linux archives still require compatible host graphics, audio and libc facilities. The supplied third-party mpv/FFmpeg builds have unresolved corresponding-source and license-fulfillment requirements; their public redistribution remains blocked. See [release status](docs/release-status.md) and [redistribution](docs/redistribution.md) for evidence and limitations.
