## Player, watch-state and native-store status (2026-10-29)

Eight additional issues were fixed after the original audit. Each was verified by running the affected path.

| Area | Change | Observed verification |
|---|---|---|
| Anime4K colour on Wayland | `main.cpp` requests desktop OpenGL 3.3 core context before `QApplication`; Qt had been producing GLES 3.2 and mpv ran its render API on it; `hq_aa` chain order fixed | On static test frame, `hq_a` mean RGB 48.9/107.3/121.5 on GLES against 120.0/124.2/126.0 on desktop GL (chain off 120.8/124.9/126.9); invariant test pins chain order |
| Resume and watched state | `WatchHistory` stores `offsets`/`durations`; playback starts at 00:00 and offers "Continue from %1?" (`Continue` / `Start over`); 90 % of known length marks episode watched and drops offset; offsets under 30 s not stored | Driven through real `PlayerDialog`: 45 s stored → Continue lands at 45.00 s, Start over stays at 0.12 s and raises `episodeResumeDeclined`, 0 s raises no prompt |
| Component install failure ("trtexec could not be created") | Linux `trt-runtime` names SONAME files pinned 3.7.0 archive contains; `trtexec` left pack's `files`: copied once by AnimeJaNai provisioning step; second copy had been failing against `QIODevice::NewOnly` | `TestNativeComponents` PASS; Linux catalogue no longer lists `trtexec` in that pack |
| 7-Zip link-field parsing | Always-printed, usually-empty `Symbolic Link =` / `Hard Link =` fields only treated as links when they carry target | Both listing modes accepted against real `aji-linux-x64.tar.zst` |
| Store root and update hygiene | `nativeRoot()` falls back to `AppLocalDataLocation/native` when executable's directory cannot hold store; trust anchored at store's parent; `pruneNativeStore()` clears abandoned `scratch/` and `*.previous` (older than a day) plus `aji-stage-*` and `*.partial` (older than an hour) at startup | A store seeded with 3-day-old scratch, stage, partial and backup lost those four while keeping the installed `trtexec`, an imported ONNX graph and just-created stage/partial entries; `TestNativeBundle` pins both directions |
| "The update ran an old build" | Every build stamps revision and build time: `--version`, startup log and `applicationVersion` | `--version` printed `0.1.0 (9372c03, built 2026-10-28T21:56:19Z)` from AppImage, portable tree and wine-run Windows payload |
| Session idle block | `IdleInhibitor` holds logind's `idle` lock per playing surface, with screen-saver interface as fallback, released when last one pauses or closes | `systemd-inhibit --list` showed block for source build and AppImage while playing, none after close |
| Runtime bundling | Every Linux artifact now ships the pinned libmpv fork instead of the host's. The published archive had no FFmpeg TLS backend (its own CLI: "No protocol handler found"), so it was rebuilt with `--enable-openssl` at the same FFmpeg tag; `MpvHandle` also names the host CA bundle because the bundled OpenSSL's compiled-in paths are the build distribution's | Through `MpvHandle`, the rebuilt runtime decoded an https HLS stream (duration 634.58 s, h264) where the published archive returned nothing; the installed `.deb` start log names the bundled runtime, and both packages were installed and removed in distribution containers |
| Bundle contents and packaging layout | The extraction filter dropped `libvulkan.so.1` as a "driver" library although the runtime links it; the deb put the binary at `/opt/mikai/bin` behind a `/usr/bin/mikai` symlink and the runtime lookup followed the symlink's directory; the deb's dependency scan merged every shipped directory into one namespace and lost `libdbus-1-3` | A bare `archlinux` container refused to load the module until the loader stayed bundled; the `/usr` prefix fixed the runtime lookup (start log: `player runtime standard stock-…`); resolving each object against its own `$ORIGIN`/RUNPATH restored `libdbus-1-3`, `libfontconfig1`, `libfreetype6` and `libzstd1` to `Depends` |
| AnimeJaNai on Linux | `isAnimeJanaiForkRuntime()` accepted only the Windows DLL's size and SHA-256, so a bundled Linux fork reported `animejanai.core.unsupported` even though its CLI lists the `animejanai` filter and the `aji_set_slot`/`aji_poll` commands the player drives. Unix modules are now identified by the fork's filter name, which a stock mpv does not contain, and by client API 2.5 or newer (the Linux fork reports 2.6, the Windows fork 2.5); a digest cannot serve there because the install rewrites each module's RUNPATH | The published Linux runtime lists the filter and its commands; the new `TestRuntimeSelection` case accepts a module carrying the marker and refuses one without it | 
| Player corner radius | Application pushes `theme::radiusSmall()` through `shell::setCornerRadius`; window controls, title bar, dock, footer chip and new `EpisodeNavButton` read it rather than constants | `EpisodeNavButton` rendered with radius 0 keeps filled corner and radius 16 cuts it; hover raised mean alpha 140.9 → 155.9 and disabled returned 70.9 |
| AnimeJaNai `Failed to create inference context` on Linux | The fork's `aji_trt` backend dlopens `libnvinfer.so.11` by bare soname, so the closure folder must be preloaded `RTLD_GLOBAL` before the filter attaches; `prepareAnimeJanaiPlan` now records `backendLibDirs` (the TRT installation root) and `VideoSurface` preloads every `.so` in it before `vf add`. AJI failures are also logged (`[animejanai] <key>: <reason>`), and the session log falls back to `AppLocalDataLocation` when the exe folder is read-only (AppImage mounts are), so AppImage runs produce a readable `mikai.log` | Fork CLI repro: with the store's `trt/` dir absent from the loader path the filter logged `libnvinfer.so.11: cannot open shared object file` then `Failed to create inference context`; with it on the path the backend initialised (`backend: TensorRT (aji_trt)`) and streamed. `TestAnimeJanaiRuntime::tensorRtPlanCarriesTheBackendLoaderDir` pins the plan field; `TestDiagnostics::aReadOnlyExeFolderFallsBackToAWritableLogFolder` pins the log fallback |
